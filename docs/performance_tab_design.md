# パフォーマンス タブ設計書 (Windows 10 タスクマネージャ互換)

## 1. 概要と目的
LiteProcManager に Windows 10 タスクマネージャの「パフォーマンス」タブに類似したリアルタイム・システムリソース監視ビューを追加する。  
既存の軽量ネイティブ C++17 / Win32 API 設計思想（外部重量級ライブラリ不使用、低メモリ・低オーバーヘッド、ライト/ダーク両テーマ、日英バイリンガル対応）を踏襲しつつ、CPU・メモリ・ネットワークの 60 秒間時系列グラフおよび詳細メトリクスを表示する。

---

## 2. タブ構成と画面レイアウト

### 2.1 メインタブ順序
`MainTab` を以下の順序に拡張する：
0. `プロセス` / `Processes` (`MainTab::kProcesses = 0`)
1. `パフォーマンス` / `Performance` (`MainTab::kPerformance = 1`)
2. `サービス` / `Services` (`MainTab::kServices = 2`)

パフォーマンスタブ表示中はプロセス固有ツールバー行（条件フィルタ行 `filter_*`、プロセス一覧 `listview_hwnd_` / `treeview_hwnd_`）を非表示にし、`PerformanceView` カスタムウィンドウをタブ直下〜ステータスバー上端まで全幅表示する。

### 2.2 画面レイアウト（2ペイン構成）
```

| [左サイドバー: 220px] | [右詳細ペイン: 可変幅]                                 |
|                       |                                                       |

| | [mini] CPU        | | 60 秒間の使用率 (%)                              100% |
| |        63% 2.10GHz| | +-------------------------+ +-----------------------+ |

| +-------------------+ | | Core 2                  | | Core 3                | |
| | [mini] イーサネット| | +-------------------------+ +-----------------------+ |
| |        Ethernet0  | |                                                       |
| |        送432 受0  | | 使用率   速度              基本速度:     2.10 GHz     |
| +-------------------+ | 63%      2.10 GHz          ソケット:     4            |

+-------------------------------------------------------------------------------+
```

- **左サイドバー（幅 220px）**:
  - 選択可能なリソースカード一覧：CPU、メモリ、アクティブなネットワークアダプター（複数 NIC 対応、縦スクロールまたはリスト配置）。
  - 各カード左側（約 54×38px）に 60 秒間のミニスパークラインを描画し、右側にタイトル・主要数値（CPU: `63% 2.10 GHz`、メモリ: `7.4/8.0 GB (92%)`、ネットワーク: アダプター名＋`送信: X / 受信: Y`）を表示。
  - ホバーおよび選択状態を `ThemeManager` パレット色（`selected_item` / `control_hover`）で明瞭に表示。
- **右詳細ペイン**:
  - **CPU ビュー**:
    - 右クリックメニューで「論理プロセッサ (`Logical processors`)」グリッド表示（デフォルト）と「全体の使用率 (`Overall utilization`)」単一グラフ表示を切り替え可能。
    - 論理コア数に応じた自動グリッド計算 (`ComputeCpuGridLayout`: 1→1x1, 2→1x2, 4→2x2, 6→2x3, 8→2x4, 12→3x4, 16→4x4 等)。
    - 左側 KPI（太字大フォント）：使用率、速度、プロセス数、スレッド数、ハンドル数、稼働時間 (`D:HH:MM:SS`)。
    - 右側ハードウェア属性：基本速度、ソケット数、物理コア数、論理プロセッサ数、仮想マシン判定、L1/L2/L3 キャッシュサイズ（取得不可時は `N/A`）。
  - **メモリ ビュー**:
    - 60 秒間のメモリ使用率グラフ（最大値 = 物理メモリ総量、例: `8.0 GB`）。
    - メモリ構成バー（使用中・キャッシュ済み・空き領域の可視化）。
    - KPI（使用中、利用可能、コミット済み、キャッシュ済み、ページプール、非ページプール）と合計物理メモリ。
  - **ネットワーク ビュー**:
    - 60 秒間の送受信デュアルグラフ（受信：実線＋塗りつぶし、送信：破線）。
    - Windows 10 準拠の自動スケール階段関数（100 Kbps → 500 Kbps → 1 Mbps → 5 Mbps → 10 Mbps → 50 Mbps → 100 Mbps → 500 Mbps → 1 Gbps → 10 Gbps）。
    - KPI（送信速度、受信速度）とアダプター詳細（アダプター名、接続の種類、IPv4、IPv6、リンク速度）。

## 4. データ収集アーキテクチャ

### 4.1 60 秒リングバッファ (`RingBuffer<T, 60>`)
- 固定サイズ配列 (`std::array<T, 60>`) によるヒープ再割当ゼロのリングバッファ。
- `MainWindow` の `IDT_PERFORMANCE_TIMER`（1000ms 間隔）により毎秒サンプリングし、各履歴へプッシュする。
- タブが非アクティブ（プロセス/サービス表示中）の間も 1 秒ごとにバックグラウンドサンプリングを継続（UI 再描画はパフォーマンスタブ表示中のみ実施）することで、タブを切り替えた瞬間に過去 60 秒間のグラフが既に描画された状態にする。

### 4.2 Win32 / NT ネイティブ API 使用一覧

| カテゴリ | 使用 API / ライブラリ | 取得内容と注意点 |
|---|---|---|
| **CPU 静的情報** | `__cpuid` (0x80000002..0x80000004, 1) | ブランド文字列、ハイパーバイザビット (ECX bit 31)。失敗時はレジストリ参照 |
| **CPU トポロジ・キャッシュ** | `GetLogicalProcessorInformationEx` | ソケット数 (`RelationProcessorPackage`)、物理コア数 (`RelationProcessorCore`)、L1/L2/L3 キャッシュ (`RelationCache`)、論理プロセッサ数 (`GetActiveProcessorCount(ALL_PROCESSOR_GROUPS)`) |
| **CPU 周波数** | `CallNtPowerInformation(ProcessorInformation, ...)` (`powrprof.lib`) | `MaxMhz` (基本速度)、`CurrentMhz` (現在速度)。`PROCESSOR_POWER_INFORMATION` を明示定義 |
| **CPU 使用率 (全体/各コア)** | `NtQuerySystemInformation(8)` (`SystemProcessorPerformanceInformation`) | `KernelTime` は `IdleTime` を含むため、`Active = (DeltaKernel - DeltaIdle) + DeltaUser` として計算し `[0, 100]` にクランプ |
| **プロセス/スレッド/ハンドル・稼働時間** | `GetPerformanceInfo`, `GetTickCount64` | システム全体のプロセス数・スレッド数・ハンドル数・稼働ミリ秒 |
| **メモリ** | `GlobalMemoryStatusEx`, `GetPerformanceInfo` | 物理合計、利用可能、使用中、コミット済み/上限、システムキャッシュ、ページ/非ページプール |
| **ネットワーク** | `GetIfTable2`, `FreeMibTable`, `GetAdaptersAddresses` (`iphlpapi.lib`, `ws2_32.lib`) | LUID で結合。ループバック・トンネル・非ハードウェア仮想フィルタを除外し、実 NIC の送受信バイト差分から `steady_clock` 経過時間で bps を算出。ヘッダ順序 (`winsock2.h` → `iphlpapi.h` → `windows.h`) を厳守 |

## 5. GDI 描画とリソース安全性
- `PerformanceView` は `WM_ERASEBKGND` で `1` を返し、`WM_PAINT` 内で `CreateCompatibleDC` + `CreateCompatibleBitmap` による完全ダブルバッファリングを行い、`BitBlt` で一括転送してチラつきを完全に防止する。
- すべての `HPEN` / `HBRUSH` / `HFONT` / `HBITMAP` / `HDC` は RAII ラッパー（デストラクタで元のオブジェクトを `SelectObject` で復元してから `DeleteObject` / `DeleteDC`）で管理し、GDI ハンドルリークをゼロに保つ。

## 6. ローカライズ・設定・テスト戦略
- **ローカライズ**: `PerformanceStrings` 構造体を介して `LanguageManager` の文字列を `PerformanceView` に注入（日本語・英語完全対応）。
- **テスト戦略**:
  - コアロジック（リングバッファ、フォーマッタ、グリッド/スケール計算、CPU デルタ計算、メモリ・ネットワーク計算）は純粋関数として切り出し、モック値で決定論的に単体テストする。
  - GDI レンダラはオフスクリーンメモリ DC に対し境界条件（0件・部分・60件、幅高さ0矩形）と `GetGuiResources(..., GR_GDIOBJECTS)` によるリークゼロ検証テストを実施する。
  - `PerformanceDataService` の統合スモークテストを実施し、`vstest.console.exe` で全件パスを確認する。
